# Руководство для агентов по sites

Это руководство определяет общие для всего репозитория инструкции для кодирующих агентов, работающих с кодовой базой sites.

## Другое:

- Текущая версия проекта: 0.0.0 (всегда обновляй номер версии).
- Текущий билд проекта: 0 (всегда обновляй номер билда).
- Соблюдай Semantic Versioning 2.0.0. Не забывай: после каждого изменения определяй: это МАЖОРНАЯ, МИНОРНАЯ ИЛИ ПАТЧ версия.
- Коммиты всегда должны быть на английском.
- Соблюдай sensible default.

## Changelog

- Каждое изменение записывай в файл `changelog.txt`.
- Никогда не удаляй записи в `changelog.txt`, только добавляй новые **сверху**.

```
version 0.0.0
build 0

Имя ИИ моделей, писавших версию:

- Исправлено: описание ошибки.
- Добавлено: описание функции.
```

## Локализация и языки:

- Не записывай текст, отображаемый конечному пользователю в функции хардкодом.
- Код, отвечающий за локализацию должен быть расширяемым: чтобы в любой момент можно было добавить много новых языков.

## Стиль кода:

- Код должен быть предсказуемым и весь написан в едином стиле: чтобы человек, прочитав немного кода сразу смог влится в кодовую базу. Не должно быть такого, что в одном случае код использует A решения, а в другом случае B.
- Кодовая база должна быть гибкой и готова к любым изменениям, даже в самых непредсказуемыых направлениях.
- Кодовая база должна быть легко масштабируемой и расширяемой.

## КАК ПИСАТЬ ПРОЕКТ

- Пиши проект на обычном JavaScript для браузера — не на TypeScript и не на Node.js.

Проект должен запускаться без сборки, транспиляции и компиляции локально командой `python3 -m http.server`. Используй HTML, CSS и браузерный JavaScript. Не добавляй зависимости или инструменты, которым нужен Node.js для запуска проекта.

При этом пиши JavaScript со строгой типизацией через JSDoc:
- В первой строке каждого JavaScript-файла ставь `// @ts-check`.
- Описывай типы через JSDoc: `@typedef`, `@param`, `@returns`, `@type`.
- Указывай типы параметров и возвращаемого значения у функций.
- Используй `const` по умолчанию, `let` — только когда переменная переназначается; не используй `var`.
- Явно обрабатывай `null` и `undefined`.
- Не используй неявный `any`; если тип неизвестен, явно обозначь это и по возможности сузь тип.
- Не используй синтаксис TypeScript: `interface`, `type`, аннотации вроде `: string` и оператор `as`.
- Используй браузерные API и возможности JavaScript, поддерживаемые современными браузерами.
- Не добавляй аннотации там, где они очевидно избыточны или ухудшают читаемость.
